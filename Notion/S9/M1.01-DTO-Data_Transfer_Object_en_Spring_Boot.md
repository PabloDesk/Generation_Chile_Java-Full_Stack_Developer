# DTO - Data Transfer Object en Spring Boot

## ¿Qué es un DTO?

Un **DTO (Data Transfer Object)** es un objeto diseñado **exclusivamente para transportar datos** entre capas, especialmente entre:

- la API (Controller)
- el mundo externo (cliente)

> [!NOTE]
>
> 💡 Un DTO no representa el dominio interno, representa el contrato de comunicación.

---

## 🧠 ¿Por qué existen los DTOs?

Los DTOs existen para resolver varios problemas comunes:

- Evitar exponer entidades internas
- Controlar qué datos se envían o reciben
- Desacoplar la API del modelo interno
- Facilitar cambios sin romper clientes
- Mejorar seguridad y claridad

---

## 📌 Responsabilidad del DTO

### ✔️ Lo que sí hace

- Transportar datos
- Definir la forma del request
- Definir la forma del response
- Limitar campos visibles
- Servir como contrato externo

### ❌ Lo que NO debe hacer

- Contener lógica de negocio
- Acceder a base de datos
- Conocer entidades internas
- Ejecutar validaciones complejas del dominio
- Tener comportamiento

---

## 🧱 DTO vs Entity

| Entity | DTO |
| --- | --- |
| Modelo interno | Contrato externo |
| Representa dominio | Representa comunicación |
| Puede tener relaciones | Suele ser plano |
| Vive en `model` | Vive en `dto` |

📌 **Nunca deben mezclarse responsabilidades**.

---

## 🧠 DTOs de entrada y de salida

Normalmente se usan distintos DTOs para:

- **Request DTO** → datos que llegan
- **Response DTO** → datos que salen

Esto permite mayor control y claridad.

---

## ⚠️ Error común

Usar directamente la entidad como DTO.

Problemas:

- Exposición de campos sensibles
- Acoplamiento fuerte
- Dificultad para versionar la API
- Cambios internos rompen clientes

---

## 🧠 DTOs y validación

Los DTOs suelen ser el lugar ideal para:

- Validaciones de formato
- Validaciones básicas de entrada

Ejemplos conceptuales:

- campos obligatorios
- tamaños
- formatos

📌 Las reglas de negocio siguen perteneciendo al `service`.

---

## 📂 Organización típica del package `dto`

```
dto/
├── UsuarioRequestDTO.java
├── UsuarioResponseDTO.java
```

📌 El nombre suele indicar claramente su uso.

---

## 🧠 DTOs y evolución de la API

Los DTOs permiten:

- cambiar el modelo interno
- mantener estable el contrato externo
- versionar APIs sin romper clientes

---

## 🧠 Regla de oro

> [!IMPORTANT]
> 
> 💡 Si un objeto cruza el límite de la aplicación, debe ser un DTO.

---

## ✅ Resumen

- DTO significa Data Transfer Object
- Transporta datos, no lógica
- Protege el modelo interno
- Define el contrato de la API
- Facilita evolución y seguridad
