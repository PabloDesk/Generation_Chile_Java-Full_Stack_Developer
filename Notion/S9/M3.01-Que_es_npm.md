# ¿Qué es npm? 📦

## 1️⃣ Sobre Node.js

**npm** es el *gestor de paquetes* de Node.js. Te permite **instalar, actualizar y gestionar dependencias** (bibliotecas) de tu proyecto. Es la puerta de entrada al **registro público npm** (npmjs.com), donde está el ecosistema de paquetes JS/Node. 

**Glosario mínimo**

- **Paquete**: lo que instalas desde el registro (una lib, CLI, etc.).
- **Módulo**: paquete utilizable como módulo de Node (conceptos relacionados).

> [Documentación oficial](https://nodejs.org/docs/latest/api/)

---

## 2️⃣  `package.json` 🗂️ (el “manifiesto” del proyecto)

Es el archivo que describe tu app/lib: nombre, versión, dependencias, scripts, etc. La mayoría de comandos de npm lo leen o lo crean/actualizan. (Ver comandos abajo)

---

## **3️⃣** Inicializar un proyecto 🚀

**Interactivo (te hace preguntas):**

```bash
npm init
```

**Rápido (valores por defecto):**

```bash
npm init -y
```

`npm init` crea o prepara tu `package.json`. También puedes usar *inicializadores* tipo `npm init <initializer>` (p. ej., plantillas `create-*`). [docs.npmjs.com](https://docs.npmjs.com/cli/v9/commands/npm-init?utm_source=chatgpt.com)

---

## **4️⃣**🔧 Instalar dependencias

**Instalar en el proyecto (local):**

```bash
npm install <paquete>
```

**Guardar como dependencia de producción (por defecto):**

```bash
npm install <paquete> --save
```

**Guardar como dependencia de desarrollo:**

```bash
npm install <paquete> --save-dev
```

**Instalar todas las que figuran en `package.json`:**

```bash
npm install
```

**Global (CLI/herramientas de sistema):**

```bash
npm install -g <paquete>
```

Cómo se resuelven e instalan paquetes y el papel de `package-lock.json` está documentado en la página de `npm install`. [docs.npmjs.com](https://docs.npmjs.com/cli/v8/commands/npm-install?utm_source=chatgpt.com)

---

## **5️⃣**🏃 Ejecutar binarios sin instalar (o locales) con **npx**

```bash
npx <comando-o-paquete>
# Ejemplo: npx create-vite@latest
```

`npx` ejecuta binarios de paquetes (locales o remotos) en un entorno temporal, útil para “usarlo y listo” sin añadirlo a dependencias. [docs.npmjs.com](https://docs.npmjs.com/cli/v8/commands/npx/?utm_source=chatgpt.com)

# **6️⃣**🧰 Scripts de npm (automatiza tareas)

En `package.json`:

```json
{
  "scripts": {
    "start": "node index.js",
    "build": "tsc -p .",
    "test": "vitest run"
  }
}
```

**Ejecutar:**

```bash
npm run build
npm start      # alias de npm run start
npm test       # alias de npm run test
```

Cómo funcionan los scripts y los “pre/post” (premyscript/postmyscript). [docs.npmjs.com+1](https://docs.npmjs.com/cli/v8/using-npm/scripts/?utm_source=chatgpt.com)

## **7️⃣**🔍 Buscar paquetes

**Desde la web:** usa la barra de búsqueda en **npmjs.com** (ordena por coincidencias en título, descripción, README y keywords). [docs.npmjs.com+1](https://docs.npmjs.com/searching-for-and-choosing-packages-to-download/?utm_source=chatgpt.com)

**Desde la terminal:**

```bash
npm search <término>
```

Hace una búsqueda lexicográfica incremental contra metadatos del registro. [docs.npmjs.com](https://docs.npmjs.com/cli/v6/commands/npm-search/?utm_source=chatgpt.com)

---

## 8️⃣📈 Elegir paquetes con criterio (cómo reconocer los “buenos”)

Al abrir un paquete en npmjs.com, revisa:

1. **Actividad y mantenimiento:** fecha del **último publish**.
2. **Descargas semanales** (indicativo, no garantía de calidad).
3. **Repositorio y issues** enlazados (mira actividad/PRs).
4. **Licencia** y **documentación** (README claro, ejemplos).
5. **TipoScript:** si incluye `types` o tipados.
6. **Salud de seguridad:** ejecuta `npm audit` en tu proyecto.

La propia documentación de npm explica cómo **buscar y elegir** paquetes (qué muestra la búsqueda y de dónde salen los datos). [docs.npmjs.com](https://docs.npmjs.com/searching-for-and-choosing-packages-to-download/?utm_source=chatgpt.com)

> Seguridad: ejecuta auditorías periódicas:
> 
> 
> ```bash
> npm audit
> npm audit fix
> ```
> 
> `npm audit` reporta vulnerabilidades conocidas y puede proponer/aplicar remediaciones (`fix`). [docs.npmjs.com+1](https://docs.npmjs.com/cli/v9/commands/npm-audit/?utm_source=chatgpt.com)
>

## 9️⃣♻️ Actualizar / listar / limpiar

**Ver árbol de dependencias instalado:**

```bash
npm ls
npm ls --depth=0        # solo primer nivel
npm ls -g --depth=0     # globales
```

[docs.npmjs.com](https://docs.npmjs.com/cli/v7/commands/npm-ls/?utm_source=chatgpt.com)

**Detectar paquetes desactualizados:**

```bash
npm outdated
npm outdated --all
```

Mira lo instalado vs. versión más reciente disponible. [docs.npmjs.com](https://docs.npmjs.com/cli/v8/commands/npm-outdated/?utm_source=chatgpt.com)

**Actualizar dependencias:**

```bash
npm update              # según rangos de semver en package.json
npm update <paquete>
```

(Recuerda que respeta los rangos de versión definidos). [docs.npmjs.com](https://docs.npmjs.com/cli/v6/commands/?utm_source=chatgpt.com)

# 🔢 Versionado semántico (semver) en npm

| Rango en `package.json` | Qué permite | Ejemplo |
| --- | --- | --- |
| `^1.2.3` | Permite actualizaciones *minor* y *patch*. Es decir: `>=1.2.3` y `<2.0.0` | `^1.2.3` permite `1.3.0`, `1.2.5` pero no `2.0.0` |
| `~1.2.3` | Permite solo actualizaciones *patch*. Se traduce como `>=1.2.3` y `<1.3.0` | `~1.2.3` permite `1.2.4`, `1.2.9` pero no `1.3.0` |
| `1.2.3` | Versión exactamente la 1.2.3, sin rango. | Solo `1.2.3` se acepta |
| `>=1.2.3 <2.0.0` | Rango explícito similar a `^1.2.3`. | Permite cualquier versión desde la 1.2.3 hasta antes de la 2.0.0 |
| `*` | Permite **cualquier versión** (no recomendado) | Permite `0.x`, `1.x`, `2.x`, etc. |
