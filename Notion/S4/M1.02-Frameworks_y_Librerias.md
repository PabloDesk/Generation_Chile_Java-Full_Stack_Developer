# Frameworks y Librerías

## 🧩 1. ¿Qué es una librería? ¿Qué es un framework?

### 🔹 **Librería**

Colección de funciones que **tú llamas** cuando las necesitas.

➡ Tú controlas el flujo.

Ejemplos: **React**, Lodash, Axios.

### 🔹 **Framework**

Conjunto de herramientas y reglas donde el framework controla **cómo se ejecuta tu aplicación**.

➡ El framework controla el flujo.

Ejemplos: **Next.js**, Angular, Express, Laravel.

### 🎓 Explicación rápida

- Una **librería** es como un *superpoder que activas cuando quieres*.
- Un **framework** es como un *mundo con reglas*: si juegas ahí, debes seguir su estructura.

# ⚛️ 2. React — La Librería moderna por excelencia

Incluye: React, Vite, JSX, componentes, hooks y Next.js

---

## 🚀 ¿Qué es React?

React es una **librería para crear interfaces de usuario** basada en:

- Componentes reutilizables
- Virtual DOM
- Renderizado eficiente
- Arquitectura declarativa

<aside>

React es uno de los pilares del desarrollo moderno porque permite **crear interfaces grandes sin perder control**.

</aside>

---

## ⚡ React + Vite → El estándar actual

Vite reemplaza a CRA por ser más rápido:

- Arranque instantáneo
- Hot Module Reload también instantáneo
- Configuración mínima
- Compatible con TypeScript, Tailwind, Chakra, etc.

### 🔧 Crear un proyecto con Vite

```bash
npm create vite@latest my-app --template react
cd my-app
npm install
npm run dev
```

---

## 💡 Ejemplo básico de React (componente moderno)

```jsx
function App() {
  const [count, setCount] = useState(0);

  return (
    <section>
      <h1>Hola React 🚀</h1>
      <button onClick={() => setCount(count + 1)}>
        Clicks: {count}
      </button>
    </section>
  );
}

export default App;
```

---

## 🏗️ Next.js → El Framework de React

Next.js agrega:

- File-based routing
- SSR (Server-Side Rendering)
- SSG (Static Site Generation)
- APIs integradas
- Optimización automática

### Ejemplo de página en Next.js 15

`app/page.jsx`

```jsx
export default function Home() {
  return <h1>Bienvenido a Next.js 15 ✨</h1>;
}
```

---

## ⭐ Buenas prácticas (React + Next)

- Divide tu UI en componentes pequeños.
- Usa hooks en vez de clases.
- Mantén la lógica separada del render.
- Evita props innecesarias (prop drilling).
- Utiliza herramientas como Zustand, Redux Toolkit o Context API para estados globales.
- Prefiere Next.js para proyectos profesionales.

# 🟦 3. Express — El Backend rápido y flexible

Incluye CommonJS + ES6, ejemplo, y MVC.

---

## ⚙️ ¿Qué es Express?

Express es un **framework minimalista para crear APIs REST**.

Es liviano, rápido y te deja armar tu arquitectura como quieras.

---

## 🧱 Express en CommonJS (lo más usado en cursos y proyectos rápidos)

### Ejemplo mínimo:

```jsx
const express = require("express");
const app = express();

app.get("/ping", (req, res) => {
  res.send({ message: "pong" });
});

app.listen(3000, () => console.log("Servidor en 3000"));
```

---

## 📦 Express en ES6 Modules (moderno)

Cuando usas Express con **import/export**, tu proyecto debe estar configurado explícitamente para trabajar con **módulos ES6**.

De lo contrario, Node arrojará errores como:

```
SyntaxError: Cannot use import statement outside a module
```

## ⚙️ 1. Habilitar ES Modules en Node.js

Agregar en tu **package.json**:

```json
{
  "type": "module"
}
```

Esto le indica a Node que **todos tus archivos .js** se ejecutarán usando **ESM (import/export)**.

---

📁 app.js (ya funciona con import/export)

```jsx
import express from "express";

const app = express();

app.get("/ping", (req, res) => {
  res.json({ message: "pong" });
});

app.listen(3000);
```

---

# 🧭 Arquitectura MVC en Express

```
/src
 ├── controllers
 ├── services
 ├── routes
 ├── models
 └── app.js
```

### Ejemplo rápido:

**route**

```jsx
router.get("/usuarios", usuarioController.listar);
```

**controller**

```jsx
export const listar = (req, res) => {
  const data = usuarioService.obtenerTodos();
  res.json(data);
};
```

**service**

```jsx
export const obtenerTodos = () => {
  return [{ id: 1, nombre: "Hackerman" }];
};
```

## ⭐ Buenas prácticas en Express

- Siempre usar middlewares para validar, autenticar y parsear.
- Separar todo por capas (MVC).
- No poner lógica en las rutas.
- Usar variables de entorno (.env).
- Evitar JSON mal formado.

# 🎨 4. Bootstrap — Framework de CSS

Incluye buenas prácticas, el tema del `!important` y alternativas mejores.

---

## ¿Qué es Bootstrap?

Framework CSS para crear interfaces rápidas con componentes listos:

botones, tarjetas, modales, navbar, formularios, etc.

Es útil para:

- Prototipos rápidos
- Proyectos simples
- Bootcamps
- Aprender CSS moderno

---

## ⚠️ Advertencia profesional sobre Bootstrap

Bootstrap usa **mucho `!important`**, lo que puede causar:

- Conflictos de estilos
- Dificultad para sobrescribir
- CSS menos mantenible

🔍 Por eso, en proyectos reales se usan alternativas mejores:

- Tailwind CSS
- Chakra UI
- Material UI

---

## Ejemplo básico:

```html
<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.0/dist/css/bootstrap.min.css" rel="stylesheet">

<button class="btn btn-primary">Haz click</button>
```

---

## Buenas prácticas con Bootstrap

- Uso moderado, no dependas 100% del framework.
- Personaliza con variables CSS o SASS.
- No abuses de los `col-` si la UI no lo requiere.
- Para proyectos grandes → evalúa Tailwind o Chakra.

# 🔄 5. Redux — Manejo de estado profesional

## ¿Qué es Redux?

Es una **librería para manejar estado global** basada en:

- un store único
- reducers
- acciones
- flujo unidireccional

Hoy se usa principalmente como:

➡ **Redux Toolkit** (RTK), versión moderna y simplificada.

---

## Ejemplo básico con Redux Toolkit

```jsx
import { createSlice, configureStore } from "@reduxjs/toolkit";

const counterSlice = createSlice({
  name: "counter",
  initialState: { value: 0 },
  reducers: {
    inc: (state) => ({ value: state.value + 1 }),
  },
});

export const { inc } = counterSlice.actions;

export const store = configureStore({
  reducer: { counter: counterSlice.reducer },
});

```

---

## ⭐ Buenas prácticas con Redux

- Usar Redux Toolkit (no Redux clásico).
- Reducers pequeños y puros.
- Evitar manejar lógica pesada en los componentes.
- Integrar con React mediante hooks:
    - `useSelector()`
    - `useDispatch()`
- Usarlo solo cuando **Context API no es suficiente**
    
    (proyectos medianos o grandes).
    

---

# 🧠 Tips generales para Frameworks y Librerías

- Aprende la **filosofía** de cada herramienta.
- Evita mezclar demasiados frameworks en un proyecto inicial.
- Mantén tu entorno actualizado.
- Practica ejemplos pequeños antes de proyectos grandes.
- Prioriza arquitectura limpia, no solo “que funcione”.
- Documenta todo desde el inicio del proyecto.
