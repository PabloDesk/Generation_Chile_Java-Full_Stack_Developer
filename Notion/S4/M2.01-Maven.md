# Maven

## 1️⃣ Sobre Maven

**Apache Maven** es una herramienta de **gestión de proyectos** y **automatización de builds** para Java (y otros lenguajes JVM). Su objetivo principal es **estandarizar** cómo se construye un proyecto: dependencias, compilación, tests, empaquetado y publicación.

Maven se basa en el concepto de **POM** (*Project Object Model*), un archivo llamado `pom.xml` donde se define:

- Qué es el proyecto (nombre, versión, packaging)
- Qué dependencias usa (por ejemplo: **JUnit**, Spring Boot, Lombok)
- Qué plugins usa para compilar, testear, empaquetar, etc.
- Reglas del build (Java version, perfiles, etc.)

A diferencia de un IDE (IntelliJ/Eclipse), **Maven no es una interfaz**, es una herramienta que ejecuta un flujo reproducible desde terminal o CI/CD.

💡 **Documentación oficial:** https://maven.apache.org/

---

## 2️⃣ ¿Por qué Maven es importante en Java?

Maven se usa porque convierte tu proyecto en algo:

✅ **Repetible** (funciona igual en tu PC, en el del equipo y en producción)

✅ **Escalable** (maneja cientos de dependencias sin dolor)

✅ **Estándar** (estructura de carpetas y comandos conocidos)

✅ **Automatizable** (ideal para pipelines CI/CD)

✅ **Profesional** (es parte del “idioma” de la industria Java)

En el mundo real, no basta con “me corre en mi IDE”; se necesita:

- Descargar dependencias sin hacerlo manual
- Ejecutar pruebas automáticamente
- Generar artefactos (`.jar`, `.war`)
- Integrarlo con GitHub Actions / Jenkins / GitLab CI

## 3️⃣ Maven vs Gradle (contexto rápido)

| Herramienta | Enfoque | Ventaja | Uso típico |
| --- | --- | --- | --- |
| **Maven** | Declarativo (XML) | Estándar, simple, muy común | Empresas Java tradicionales |
| **Gradle** | Programable (Groovy/Kotlin) | Más flexible y rápido en builds grandes | Android, proyectos modernos |

<aside>

💡
En cursos y bootcamps, **Maven suele ser idea**l porque enseña estructura y estándares sin distraer con demasiada configuración.

</aside>

## 4️⃣ Estructura estándar de un proyecto Maven

Maven impone una estructura “normal” (convención) que te ayuda a organizar código productivo y pruebas:

```
mi-proyecto/
 ├── pom.xml
 └── src/
     ├── main/
     │   └── java/        ← código productivo
     └── test/
         └── java/        ← pruebas (JUnit)

```

Esto permite que `mvn test` sepa exactamente dónde buscar las pruebas.

## 5️⃣ ¿Qué es el `pom.xml`?

Es el archivo central del proyecto Maven.

📌 **Ejemplo típico (con JUnit 5):**

```xml
<project>
  <modelVersion>4.0.0</modelVersion>

  <groupId>com.ejemplo</groupId>
  <artifactId>mi-proyecto</artifactId>
  <version>1.0.0</version>

  <properties>
    <maven.compiler.release>21</maven.compiler.release>
  </properties>

  <dependencies>
    <dependency>
      <groupId>org.junit.jupiter</groupId>
      <artifactId>junit-jupiter</artifactId>
      <version>5.10.2</version>
      <scope>test</scope>
    </dependency>
  </dependencies>
</project>

```

### ¿Qué significa `scope test`?

Significa que esa librería:

- Se usa **solo para pruebas**
- No se incluye en el artefacto final de producción

## 6️⃣ Comandos básicos de Maven (los más usados)

| Comando | Qué hace |
| --- | --- |
| `mvn -v` | Muestra versión de Maven (verifica instalación) |
| `mvn clean` | Borra el build anterior (`target/`) |
| `mvn test` | Compila y ejecuta las pruebas |
| `mvn package` | Ejecuta tests y genera `.jar/.war` |
| `mvn clean package` | Limpia y vuelve a empaquetar |
| `mvn install` | Instala el artefacto en el repositorio local (`~/.m2`) |

<aside>

💡
En JUnit, el comando clave para clase suele ser: **mvn test**

</aside>

## 7️⃣ Guía de instalación de Maven

### ✅ Requisito previo

Maven requiere Java instalado (JDK). Para cursos modernos, lo típico es:

- **JDK 21 (LTS)**

### Windows

1. Descargar Maven desde el sitio oficial: https://maven.apache.org/download.cgi
2. Extraer (por ejemplo en `C:\apache-maven-3.x.x`)
3. Agregar al `PATH` la ruta `...\bin`
4. Verificar en terminal:

```bash
mvn -v
```

### macOS (Homebrew)

```bash
brew install maven
mvn -v
```

### Linux (Ubuntu/Debian)

```bash
sudo apt update
sudo apt install maven
mvn -v
```

<aside>

⚠️
Si `**mvn -v`** falla, el problema casi siempre es:
- Maven no está en el PATH
- Java no está instalado (o JAVA_HOME mal configurado)

</aside>

## 8️⃣ ¿Dónde guarda Maven las dependencias?

Maven descarga dependencias desde **Maven Central** y las guarda localmente en:

- Windows: `C:\Users\TU_USUARIO\.m2\repository`
- Linux/macOS: `~/.m2/repository`

Eso evita descargar lo mismo una y otra vez.

---

## 9️⃣ Maven y JUnit: por qué van juntos en una clase

Para enseñar JUnit de forma realista:

- Maven agrega JUnit como dependencia
- Las pruebas viven en `src/test/java`
- Se ejecutan con `mvn test`
- Esto se integra directo a CI/CD

✅ Resultado: lo que aprenden sirve en proyectos reales.
