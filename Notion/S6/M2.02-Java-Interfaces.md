# Java - Interfaces

## 🎯 Objetivo de esta subpágina

Aprender a usar **interfaces** para definir **comportamientos comunes** entre clases, **sin obligarlas a compartir una herencia**.

Aquí veremos:

- Qué es una interfaz
- Cuándo usarla
- Cómo se implementa
- Diferencia con abstracción
- Cómo se combina con polimorfismo

---

## 🧠 ¿Qué es una Interfaz?

Una **interfaz** define **qué puede hacer una clase**, pero **no dice cómo lo hace**.

En otras palabras:

> Una interfaz es un contrato de comportamiento.
> 

Las clases que la implementan **se comprometen** a cumplirlo.

---

## 🧩 Idea clave (frase para clase)

> La herencia define lo que una clase ES.
La interfaz define lo que una clase PUEDE HACER.
> 

---

## 🔄 Problema que resuelve la interfaz

Hasta ahora:

- `Guerrero` y `Mago` heredan de `Personaje`
- Ambos atacan

Pero…

❓ ¿Qué pasa si mañana tenemos otra clase que **NO es un Personaje**, pero **también ataca**?

Ejemplo:

- Torre
- Trampa
- Invocación
- Mascota

👉 **No todo puede heredar de `Personaje`.**

---

## 🧠 Solución: Interfaces

Creamos una interfaz que represente el comportamiento:

> “Atacar”
> 

---

## 🧱 Definición de la interfaz

```java
interface Atacante {
    void atacar();
}

```

📌 Características importantes:

- No tiene atributos
- No tiene implementación
- Todos los métodos son implícitamente `public`

---

## 🧬 Usando interfaz + abstracción juntos

### Clase abstracta `Personaje`

```java
abstract class Personaje {

    protected String nombre;
    protected int vida;

    Personaje(String nombre, int vida) {
        this.nombre = nombre;
        this.vida = vida;
    }

    void mostrarEstado() {
        System.out.println(nombre + " | Vida: " + vida);
    }
}

```

---

### `Guerrero` implementa la interfaz

```java
class Guerrero extends Personaje implements Atacante {

    Guerrero(String nombre, int vida) {
        super(nombre, vida);
    }

    @Override
    public void atacar() {
        System.out.println(nombre + " ataca con espada ⚔️");
    }
}

```

---

### `Mago` implementa la interfaz

```java
class Mago extends Personaje implements Atacante {

    Mago(String nombre, int vida) {
        super(nombre, vida);
    }

    @Override
    public void atacar() {
        System.out.println(nombre + " lanza un hechizo ✨");
    }
}

```

---

## 🔁 Polimorfismo usando INTERFACES

```java
List<Atacante> atacantes = new ArrayList<>();

atacantes.add(new Guerrero("Thor", 100));
atacantes.add(new Mago("Merlín", 80));

for (Atacante a : atacantes) {
    a.atacar();
}

```

✔ No sabemos qué clase es

✔ Solo nos importa que **ataque**

✔ Código limpio y extensible

---

## 🧠 Diferencia clara: Abstracción vs Interface

| Concepto | Clase abstracta | Interface |
| --- | --- | --- |
| Herencia | Una sola | Múltiples |
| Atributos | Sí | No |
| Métodos con código | Sí | No (por ahora) |
| Rol | Base común | Contrato |

📌 Java **NO permite herencia múltiple**,

pero **SÍ permite implementar múltiples interfaces**.

---

## 🔥 Ejemplo potente (muy didáctico)

```java
class Torre implements Atacante {

    @Override
    public void atacar() {
        System.out.println("La torre dispara una flecha 🏹");
    }
}

```

👉 `Torre`:

- ❌ No es Personaje
- ✅ Puede atacar

---

## 🧠 Idea clave final

> Las interfaces permiten compartir comportamientos
sin forzar una relación de herencia.
>

## 🧪 Ejercicio guiado — Interfaces

### 🎯 Consigna

1. Crear interfaz `Curable`
2. Definir método `curar()`
3. Implementar `Curable` en `Mago`
4. Crear una lista `List<Curable>`
5. Ejecutar `curar()` sin saber el tipo concreto

---

### Solución esperada (idea)

```java
List<Curable> curables = new ArrayList<>();
curables.add(new Mago("Merlín", 80));

for (Curable c : curables) {
    c.curar();
}

```
