# **Challenger Grupal - Sistema de Vehículos de Reparto**

## 🎯 Contexto del problema

Una empresa de logística necesita un sistema en consola para gestionar sus **vehículos de reparto**.

La empresa trabaja con distintos tipos de vehículos, por ejemplo:

- Camiones
- Furgones
- Motocicletas de reparto

Cada vehículo tiene información común, pero también características propias según su tipo.

El sistema debe permitir registrar vehículos, mostrarlos, calcular información general y demostrar claramente el uso de:

- **Encapsulación**
- **Herencia**
- **Polimorfismo**

Este challenger está pensado para que el equipo practique una transición real desde ejercicios estructurados hacia una lógica orientada a objetos.

---

## 📌 Reglas generales del challenger

- Proyecto en Java
- Usar `Scanner` para la interacción
- Menú principal con `do-while`
- Aplicar **POO sí o sí**
- Validar entradas
- El programa **no debe romperse**
- El código debe ser **claro, ordenado y entendible por cualquier integrante del grupo**
- Se debe trabajar en equipo y repartir responsabilidades

---

## 🧠 Objetivo técnico del challenger

En este ejercicio deben aplicar únicamente los siguientes pilares:

### 1️⃣ Encapsulación

Cada clase debe tener sus atributos `private` y su acceso controlado mediante:

- `getters`
- `setters`
- validaciones cuando corresponda

---

### 2️⃣ Herencia

Deben crear una clase base general para representar un vehículo y luego clases hijas para los distintos tipos.

---

### 3️⃣ Polimorfismo por sobrescritura

Cada tipo de vehículo debe redefinir un comportamiento común, por ejemplo:

```java
mostrarDetalle()
```

o

```java
calcularCostoOperacion()
```

La idea es que todos los vehículos compartan un mismo método, pero que cada clase hija lo implemente a su manera.

---

### ⭐ Bonus opcional — Sobrecarga

Si el grupo ya se siente cómodo, puede agregar métodos sobrecargados, por ejemplo:

```java
registrarVehiculo(String patente, String marca)
registrarVehiculo(String patente, String marca, double capacidadCarga)
```

o

```java
mostrarDetalle()
mostrarDetalle(boolean mostrarTipoTecnico)
```

## 🧩 Tema del sistema

El sistema debe gestionar vehículos de reparto de una empresa.

### Tipos sugeridos:

- `Camion`
- `Furgon`
- `MotoReparto`

---

## 🏗️ Estructura mínima obligatoria

Deben crear al menos estas clases:

### 1️⃣ Clase base

```java
Vehiculo
```

### 2️⃣ Clases hijas

```java
Camion
Furgon
MotoReparto
```

### 3️⃣ Clase principal

```java
Main
```

---

## 📦 Clase base obligatoria: `Vehiculo`

La clase `Vehiculo` debe tener atributos encapsulados como mínimo:

- patente
- marca
- modelo
- capacidadCarga
- disponible

Ejemplo:

```java
private String patente;
private String marca;
private String modelo;
private double capacidadCarga;
private boolean disponible;
```

---

## 🔒 Requisitos de encapsulación

Todos los atributos deben ser `private`.

Deben existir métodos `get` y `set`.

Deben validar al menos lo siguiente:

- La patente no puede venir vacía
- La marca no puede venir vacía
- La capacidad de carga no puede ser negativa
- El estado disponible debe manejarse correctamente

---

## 🧬 Requisitos de herencia

Las clases hijas deben extender de `Vehiculo`.

Ejemplo conceptual:

```java
public class Camion extends Vehiculo
public class Furgon extends Vehiculo
public class MotoReparto extends Vehiculo
```

Cada una debe agregar al menos **un atributo propio**.

### Ejemplos posibles:

### `Camion`

- número de ejes

### `Furgon`

- volumen interior

### `MotoReparto`

- tiene caja térmica

---

## 🎭 Requisitos de polimorfismo

Todas las clases hijas deben sobrescribir un método común de la clase padre.

### Método sugerido:

```java
public void mostrarDetalle()
```

Cada vehículo debe mostrar su información de forma personalizada.

### Ejemplo esperado:

- Un camión puede mostrar patente, marca, capacidad y número de ejes
- Un furgón puede mostrar patente, marca, capacidad y volumen interior
- Una moto puede mostrar patente, marca y si tiene caja térmica

La idea es que desde una colección de tipo `Vehiculo`, cada objeto responda según su clase real.

---

## 📚 Colección obligatoria

Deben usar una colección para almacenar los vehículos registrados.

Ejemplo:

```java
List<Vehiculo> vehiculos = new ArrayList<>();
```

Esto es importante porque permitirá aplicar polimorfismo real.

## 🔹 Opción 1 — Registrar camión

### Requisitos

- Pedir los datos generales del vehículo
- Pedir el dato específico del camión
- Crear un objeto `Camion`
- Guardarlo en la lista

### Validaciones

❌ No permitir patente vacía

❌ No permitir patentes duplicadas

❌ No permitir capacidades negativas

---

## 🔹 Opción 2 — Registrar furgón

### Requisitos

- Pedir los datos generales
- Pedir el atributo específico del furgón
- Crear el objeto
- Guardarlo en la lista

### Validaciones

❌ No permitir duplicados

❌ No permitir volumen inválido

---

## 🔹 Opción 3 — Registrar moto de reparto

### Requisitos

- Pedir datos generales
- Pedir si tiene caja térmica
- Crear el objeto
- Guardarlo en la lista

### Validaciones

❌ No permitir patente repetida

❌ No permitir campos vacíos

---

## 🔹 Opción 4 — Mostrar todos los vehículos

### Requisitos

- Recorrer la lista de vehículos
- Mostrar el detalle de cada uno
- Debe verse el polimorfismo en acción usando el método sobrescrito

Ejemplo conceptual:

```java
for (Vehiculo vehiculo : vehiculos) {
    vehiculo.mostrarDetalle();
}
```

---

## 🔹 Opción 5 — Mostrar vehículos disponibles

### Requisitos

- Mostrar solo los vehículos cuyo estado sea disponible
- Debe funcionar correctamente sin importar el tipo de vehículo

---

## 🔹 Opción 6 — Marcar vehículo como no disponible

### Requisitos

- Pedir patente
- Buscar el vehículo
- Cambiar su estado a no disponible

### Validaciones

❌ No permitir buscar una patente inexistente

❌ Mostrar mensaje claro si no se encuentra

---

## 🔹 Opción 7 — Mostrar reporte general

### Debe mostrar como mínimo:

- Total de vehículos registrados
- Total de camiones
- Total de furgones
- Total de motos de reparto
- Total disponibles
- Total no disponibles

Además, debe listar todos los vehículos con un formato claro.

Ejemplo:

```bash
Patente | Tipo | Marca | Modelo | Disponible
```

---

## 🧪 Validaciones obligatorias

✔ No permitir patentes duplicadas

✔ No permitir datos vacíos

✔ No permitir números negativos donde no corresponda

✔ No permitir marcar como no disponible un vehículo inexistente

✔ Mostrar mensajes claros de error

✔ El programa no debe caerse por una mala entrada del usuario

---

## 🧱 Requisitos mínimos de diseño

El proyecto debe demostrar claramente:

- Uso de una **superclase**
- Uso de **subclases**
- Uso de **atributos privados**
- Uso de **getters y setters**

## ⭐ Bonus opcional

Si el equipo quiere subir el nivel, puede agregar una o varias de estas mejoras:

### Bonus 1 — Sobrecarga

Crear métodos con el mismo nombre pero diferentes parámetros.

Ejemplo:

```java
public void mostrarDetalle()
public void mostrarDetalle(boolean mostrarEstadoTecnico)
```

---

### Bonus 2 — Método extra polimórfico

Además de `mostrarDetalle()`, pueden sobrescribir otro método como:

```java
calcularConsumoEstimado()
```

Cada tipo de vehículo podría devolver un valor distinto según su naturaleza.

---

### Bonus 3 — Filtro por tipo

Permitir mostrar solo camiones, solo furgones o solo motos.
